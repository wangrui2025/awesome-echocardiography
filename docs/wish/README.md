# 愿望系统

这个目录保存一种和 README、运行手册、设计规范、事故复盘都不同的长期文件：**愿望**。

它回答的不是“代码怎么实现”，而是：

> **这个网站为什么存在？当两种设计都说得通、局部规则彼此拉扯，或者未来的 Agent 已经忘记我们最初为什么这样做时，我们最希望这个网站最终成为什么？**

“愿望”允许变化。最重要的是始终有一份很短的当前愿望，同时保留过去愿望被替换的原因。

## 为什么叫“愿望”

“设计哲学”很容易变成任何网站都成立的套话。愿望先回答“我做这个网站到底想帮助自己或读者解决什么问题”，设计解释再回答“为了实现这个愿望，网站应该怎样组织”。

## 四个文件

- `LATEST.md`：当前愿望。最短、最高层的产品意图。
- `DESIGN.md`：只解释当前愿望怎样推导成本网站自己的设计，可按 L0/L1/L2/L3 展开。
- `ARCHIVE.md`：被替换的旧愿望、日期和替换理由。默认不读。
- `README.md`：也就是本文件，只定义愿望机制。

## Agent 什么时候读什么

```text
小的用户可见文案 / 局部设计
→ 读 LATEST.md

首页、导航、信息架构、页面角色、主要交互、产品方向
→ 读 LATEST.md + DESIGN.md

追溯“以前为什么不是这样”
→ 再读 ARCHIVE.md
```

不要为了仪式感每次都读 Archive。

## Authority 顺序

```text
当前 owner 明确指令
+ 事实 / 科学 authority / 安全边界 / 可执行真相
        ↓
docs/wish/LATEST.md
        ↓
docs/wish/DESIGN.md
        ↓
具体页面设计与局部实现
        ↓
docs/wish/ARCHIVE.md
```

愿望决定“我们想成为什么”，不能修改“真实发生了什么”。

## 更新流程

只有中心思想真的变化时才更新：

1. 确认这是中心愿望变化，而不是局部实现调整；
2. 把旧 LATEST 的核心内容追加到 ARCHIVE；
3. 写清日期和替换理由；
4. 更新 LATEST；
5. 同步更新 DESIGN；
6. 确认 AGENTS 或 Agent router 仍能把未来 Agent 引到这里。

## 不要把这里变成杂物间

命令怎么跑属于运行手册；实验或论文事实属于 evidence；组件怎么实现属于工程文档；事故属于 closeout/history；通用网页准则属于共享设计规范；当前 PR 状态属于 live handoff。

愿望目录只保存**当前中心意图、它的项目特有设计推导，以及被替换的旧中心意图**。
